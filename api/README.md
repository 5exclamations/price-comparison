# api/ — FastAPI поверх схемы из db/

SQLAlchemy 2.0 async на psycopg3, Pydantic v2, uvicorn.

```bash
pip install -r api/requirements.txt

export QIYMET_DATABASE_URL=postgresql+psycopg://qiymet@localhost:5432/qiymet
export QIYMET_REDIS_URL=redis://localhost:6379/0

uvicorn api.main:app --reload
open http://localhost:8000/docs
```

Требует поднятой схемы (`cd db && alembic upgrade head`) и залитых данных
(`python3 db/import_sqlite.py --sqlite pipeline/qiymet.db`).

## Эндпоинты

| маршрут | что делает |
|---|---|
| `GET /v1/search` | поиск по названию (trigram) и по штрихкоду, курсорная пагинация |
| `GET /v1/product/{id}` | карточка: цены по всем сетям, для Bravo — по зоне магазина |
| `GET /v1/product/{id}/history` | точки графика + события «акция началась/кончилась» |
| `GET /v1/deals` | лента акций по НАСТОЯЩЕЙ скидке, с флагом накрутки |
| `GET /v1/stores` | магазины, для сетей с единой ценой — одна запись на сеть |
| `GET /v1/health` | возраст данных по каждой сети |
| `POST /v1/devices` | регистрация анонимного устройства и токена FCM |
| `GET/POST /v1/watches`, `DELETE /v1/watches/{id}` | подписки на падение цены |

Подписки и уведомления описаны отдельно — см. [notify/README.md](../notify/README.md).

## Два правила, которые держат весь контракт

**Деньги.** Любое денежное поле — целое число гяпиков, имя заканчивается на
`_minor`. Ни манатов, ни float в JSON нет нигде. Тест
`test_money_fields_are_integers_in_schema` проверяет это прямо по OpenAPI, чтобы
сгенерированные модели Flutter не получили `double`.

**Время наблюдения.** Рядом с каждой ценой лежит `observed_at`. Цена без времени
— враньё: сеть могла не обновляться сутки, и `/v1/health` покажет это явно.

## Bravo и выбор магазина

У Bravo четыре измеренные ценовые зоны, и на одном товаре они дают разные цены:

```
bravo C   447   bravo A1  449   bravo A2  449   bravo B  475
```

Поэтому:

* **без** `store_id` карточка отдаёт все четыре зоны, каждая с
  `requires_store_selection: true`, сеть попадает в `needs_store_selection`, и в
  подсчёте `best_price_minor` **не участвует**;
* **с** `store_id` магазина Bravo остаётся ровно его зона, флаги сняты.

Это прямая реализация правила из CLAUDE.md: показывать цену Bravo без выбора
магазина нельзя. Сети с единой ценой (Bazarstore, Araz, SPAR, Neptun, Rahat)
схлопываются в одну строку, даже если филиалов в дампе несколько: у Araz их два,
но прайс один, и показывать оба значило бы намекать на несуществующий выбор.

## Настоящая скидка

`/v1/deals` сортируется по `real_discount`, а не по заявленной сетью. Настоящая
скидка считается от медианы неакционных цен на тот же штрихкод в **других**
сетях — логика перенесена из `pipeline/honesty.py` в матвьюху `deal_honesty`
(миграция 0005) и сверена с оригиналом построчно: 2935 строк, совпадение до
шестого знака.

Отдаются оба числа плюс `inflation` и `inflated` (накрутка больше 15 п.п.).

```json
{
  "price_minor": 169, "old_price_minor": 680, "market_price_minor": 714,
  "claimed_discount": 0.751, "real_discount": 0.763,
  "inflation": -0.012, "inflated": false
}
```

Витрину надо пересобирать после каждого прогона сбора:

```sql
SELECT refresh_after_crawl();
```

## Кеш, ETag, Cache-Control

Ответы кешируются на 5 минут. **Ключ всегда включает `store_id`** — иначе
клиент, выбравший зону C, получил бы ответ, посчитанный для зоны B. Это
корректность, а не оптимизация.

`ETag` и `Cache-Control` ставит middleware на все успешные GET разом, а не
каждый маршрут руками: забытый заголовок на одном эндпоинте иначе не видно до
продакшена. `If-None-Match` отдаёт 304 без тела. Заголовок `X-Cache: hit|miss`
показывает, откуда пришёл ответ.

Исключение — `/v1/health`: 30 секунд вместо 5 минут. Смысл эндпоинта в том,
чтобы ответить, свежи ли данные **прямо сейчас**, и пятиминутный кеш задерживал
бы предупреждение об аварии сбора ровно на пять минут.

Без `QIYMET_REDIS_URL` кеш работает в памяти процесса. Для одного процесса это
рабочий вариант, для нескольких воркеров — нет: у каждого будет свой кеш.

## Нормализация поиска

`api/normalize.py` обязан давать ровно то же, что SQL-функция `qiymet_norm`:
индекс построен по SQL-выражению, и расхождение хоть на одном символе заставит
поиск молча терять товары. Совпадение проверяется тестом
`test_python_normalize_matches_sql` на живой базе.

Порядок шагов из CLAUDE.md: сначала замена `İIıƏəÖöÜüÇçŞşĞğ` и кириллических
двойников, **потом** нижний регистр, потом NFD и сброс комбинирующих знаков.
Обратный порядок ломает `İ`: `lower('İ')` даёт `i` + U+0307, и «milka»
перестаёт находить «MİLKA».

Регистр кириллицы сворачивается таблицей замен, а не функцией `lower()`, потому
что `lower()` в Postgres **зависит от локали базы**: в кластере с `--locale=C`
`lower('Щ')` возвращает `'Щ'`. Функция стоит в индексе, так что от локали
зависело бы его содержимое.

## Пагинация

Курсорная, не offset. Лента акций пересобирается после каждого прогона, и
`OFFSET 40` показал бы товары, часть которых уже была на предыдущей странице.
Курсор непрозрачный (base64 от JSON) и всегда содержит уникальный ключ последним:
в `/v1/deals` это `deal_id`, в `/v1/search` — `product_id`.

`deal_id` в ленте — устойчивый идентификатор акции. Один товар даёт несколько
акций (по одной на сеть и зону), поэтому `product_id` для этого не годится.

## Тесты

```bash
QIYMET_DATABASE_URL=postgresql+psycopg://qiymet@localhost:5432/qiymet \
    pytest -q
```

61 тест против **настоящего** Postgres со схемой из `db/` и залитым `qiymet.db`.
Базу не мокаем: половина логики — это SQL (матвьюха честности, схлопывание зон,
trigram-поиск), и на моках она не проверялась бы вовсе. Redis подменяется на
`fakeredis`, который говорит на настоящем протоколе; рабочий класс `RedisCache`
при этом исполняется как есть.

Покрыто, помимо счастливых путей: пустой результат, карантинный товар,
несуществующий `store_id`, испорченный курсор, отсутствие пересечений между
страницами, совпадение Python и SQL нормализации, наличие `ETag` на каждом GET,
304 по `If-None-Match`, зависимость ключа кеша от `store_id`.

## Известные ограничения дампа

Не дефекты API — дыры в данных, которые API честно показывает, а не маскирует.

* **`stores.lat/lon` пусты у всех 9 магазинов.** `distance_m` всегда `null`,
  сортировать по расстоянию нечем. В ответе `/v1/stores` есть поле
  `coordinates_known` — сейчас там ноль. Формула гаверсинуса написана и
  заработает, как только координаты появятся.
* **`products.category` пуста на 100%** (36 214 из 36 214). Фильтр
  `/v1/deals?category=` реализован, но на этих данных всегда вернёт пустой
  список.
* **История в дампе — один прогон.** `/v1/product/{id}/history` отдаёт точки, но
  событий не будет, пока не накопится второй прогон: `price_observations`
  пишется только при изменении цены.
