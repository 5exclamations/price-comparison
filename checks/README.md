# Проверки

Двенадцать проверок: восемь по данным, четыре по клиенту. Задача не «покрыть
код тестами», а поймать ровно те поломки, которые уже случались.

Любая упавшая блокирует деплой: джоб `deploy` в `.github/workflows/ci.yml`
зависит от всех трёх джобов с проверками, а `needs` в GitHub Actions не
запускает зависимый джоб, если хоть один из указанных упал.

## Как запустить

```bash
export DATABASE_URL=postgresql+psycopg://qiymet@localhost:5432/qiymet

cd db && alembic upgrade head && cd ..
python3 db/import_sqlite.py --sqlite pipeline/qiymet.db

python3 -m checks.runner                # прогнать и напечатать
python3 -m checks.runner --source crawl # и записать в dq_runs (на проде)
pytest -q checks/tests                  # то же самое как pytest
```

Клиент:

```bash
cd app && flutter test
```

## Восемь проверок данных

| № | Что проверяет | Какую поломку ловит |
|---|---|---|
| 1 | Ни одной цены ≤ 0 | Разбор вернул пустую строку. Ноль мгновенно становится лучшей ценой и утаскивает всю выдачу |
| 2 | У акции старая цена больше текущей | «Было 10, стало 12»: скидка уходит в минус, позиция всплывает в ленте выгод |
| 3 | Нет дублей `chain_sku` внутри магазина | `UNIQUE (chain_id, store_id, chain_sku)` не ловит дубли при пустом `store_id`: NULL не равен NULL |
| 4 | Нет дублей EAN среди канонических товаров | Склейка развалилась: цены делятся между карточками, и везде «есть в 1 сети» |
| 5 | Медиана цены сети в 0.30–50 ₼ | Слаг `grandmart` выглядел как бакинский магазин и отдавал 596 товаров, но был точкой другой страны с медианой 1014 ₼ |
| 6 | Фасовка распознана у ≥85% позиций, и у каждой сети ≥80% | Сломался `units.py`. Без фасовки нельзя сравнить килограмм с килограммом |
| 7 | Склейки не упали больше чем на 10% | Самая незаметная смерть продукта: цены на месте, экраны работают, сравнивать нечего |
| 8 | Данные каждого **магазина** свежее 12 часов | Человек съездит по вчерашней цене, не найдёт её и удалит приложение |

Каждый запрос возвращает **нарушителей**, а не их количество: дежурный в три
часа ночи видит `bazarstore/30013586 цена 0`, а не «1 строка».

### Почему проверка 8 смотрит по магазинам, а не по сетям

Сбор молча переживает потерю отдельной точки: коннектор печатает
«ПРОПУЩЕН <slug>» и идёт дальше. У Bravo четыре ценовые зоны с разными ценами.
Если отвалилась одна, при подсчёте по сети три оставшиеся тянут
`max(observed_at)` наверх — проверка говорит «Bravo свежий», а люди, выбравшие
выпавшую точку, видят вчерашние цены без единого предупреждения.

Порог тот же, 12 часов. У сетей с единой ценой `store_id` пуст, и там это
по-прежнему одна строка: разрез ничего не меняет там, где менять нечего.

Та же логика теперь в трёх местах сразу, и они обязаны совпадать: проверка 8,
`/v1/health` (поле `stale_store_ids`) и `watchdog.sh`.

### Почему проверка 6 смотрит и по сетям

Замерено на настоящем дампе: если разбор фасовки упадёт в ноль у одной
небольшой сети, общая доля опустится с 88.0% лишь до 85.3% — выше порога, и
проверка по базе целиком поломку **пропустит**. Ловит только разрез по сетям.

Это не рассуждение, а воспроизведённый опыт: при подсадке сети из 50 позиций
без фасовки общая доля стала 87.9% (порог 85%, прошла бы), а разрез показал
`grandmart 0.0%`.

### Почему в CI пропускается проверка 8

База в CI поднимается из дампа, лежащего в репозитории, и он заведомо старше
двенадцати часов. Там проверка мерила бы возраст файла, а не работу сбора,
поэтому CI зовёт раннер с `--allow-stale`, а пропуск печатается отдельным
словом «ПРОПУЩЕНА» и пишется в историю прогонов.

Порог при этом не трогается: смягчить его значило бы выключить проверку и на
проде тоже. `--allow-stale` вместе с `--source crawl` раннер не принимает.

## Четыре проверки клиента

| № | Файл | Что ловит |
|---|---|---|
| 9 | `test/core/text_test.dart` | Нормализацию İ, Ə, Ğ, Ş и смесь латиницы с кириллицей |
| 10 | `test/design/price_text_golden_test.dart` | Показ денег: 0, 5 и 199999 гяпиков, с акцией и без |
| 11 | `test/presentation/store_change_invalidates_prices_test.dart` | Смена магазина обязана выбросить цены прошлой точки |
| 12 | `test/integration/main_path_test.dart` | Онбординг → поиск «süd» → карточка → список → итог |

Проверка 9 при первом же запуске нашла две настоящие поломки:

* клиент не сворачивал кириллические двойники (`А Е О С Р Х У К`), которые
  сворачивает серверная `qiymet_norm`, — локальный фильтр прятал то, что
  сервер уже нашёл;
* и клиент, и SQL были **не идемпотентны на «Ё»**: первый проход давал
  кириллическую «е», второй сворачивал её в латинскую «e». Клиент нормализует
  запрос у себя, сервер применяет функцию ещё раз — «мёд» переставал находить
  «Мёд». Починено миграцией `0009`, там же проверка идемпотентности прямо
  внутри миграции.

Проверка 12 нашла третью: выбор магазина Bravo мгновенно выбрасывал из
онбординга, вторую сеть отметить было уже нельзя, а кнопка «Продолжить»
не нажималась никогда.

## Прогон на эмуляторе

`app/integration_test/` — то, чего не показывает ни один widget-тест: они
гоняются на `flutter_tester`, где нет ни плагинов, ни Skia, ни настоящей
файловой системы.

| сценарий | что ловит |
|---|---|
| основной путь + снимки | регистрацию плагинов, слияние манифестов, реальную вёрстку |
| шрифт `ə ğ ş ç ö ü ı` | подстановку системного шрифта вместо Inter |
| тёмная тема | съеденный контраст цены |
| авиарежим | список покупок обязан открыться из drift без сети |

Гоняется джобом `integration-android` на `reactivecircus/android-emulator-runner`,
**API 21** — той самой нижней планке, которую объявляет `build.gradle.kts`. На
свежем API всё работает и так, а телефон человека, ради которого её понижали,
остался бы непроверенным.

Снимки экрана уезжают артефактом `android-screenshots` и выкладываются даже при
падении: картинка последнего экрана объясняет причину быстрее лога.

```bash
# локально, на подключённом устройстве
cd app && flutter drive \
  --driver=test_driver/integration_test.dart \
  --target=integration_test/app_flow_test.dart \
  --dart-define=QIYMET_SCREENSHOTS=true
```

`flutter test integration_test/` без устройства во Flutter 3.47 не работает:
инструмент ищет подключённое устройство и останавливается. Поэтому тёмная тема
и авиарежим продублированы headless-двойниками в
`test/integration/dark_and_offline_test.dart` — данные у них общие
(`test/fakes/app_fakes.dart`), чтобы «прошло локально» и «прошло на эмуляторе»
не начали означать разное.

### Golden-эталоны

Лежат в `app/test/design/goldens/`. Обновляются командой:

```bash
cd app && flutter test --update-goldens test/design/price_text_golden_test.dart
```

Обновлять их, «чтобы тест позеленел», нельзя: сначала надо посмотреть на
картинку с разницей в `test/design/failures/` (в CI она выкладывается
артефактом при падении) и понять, что именно изменилось.

Шрифт в golden-тестах грузится настоящий: без `FontLoader` flutter_test
рисует прямоугольники вместо букв, и эталон перестаёт проверять то, ради чего
заведён, — в частности `ə` и `₼`.

## Что происходит на проде, когда проверки падают

После каждого прогона сбора:

```bash
python3 -m checks.runner --source crawl
```

Результат пишется в `dq_runs` **всегда**, и при провале тоже. `/v1/health`
отдаёт последний прогон в поле `data_quality`, приложение читает его и
показывает плашку «данные обновляются» вместо подозрительных цифр.

Молчать в этот момент нельзя: человек съездит в магазин по неверной цене и
не вернётся. Пустой экран с честной плашкой он простит, вранью — нет.

Отдельно: «прогонов ещё не было» и «прогон прошёл» — разные вещи. При пустой
таблице `dq_runs` API отвечает `passed: false`, то есть качество не
подтверждено, и плашка показывается.
