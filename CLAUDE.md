# qiymət — сравнение цен в супермаркетах Азербайджана

Клиент: Flutter (iOS + Android). Бэкенд: FastAPI + PostgreSQL.

Языки интерфейса: азербайджанский (основной), русский, английский.

Валюта: манат (AZN). **Все деньги в коде — целые числа в гяпиках. Никакого float.**

## Данные и сбор информации

Python-пайплайн (папка `pipeline/`) собирает данные с шести сетей:
- Bazarstore
- Bravo
- Araz
- SPAR
- Neptun
- Rahat

Схема БД пайплайна: `pipeline/schema.sql`.

## Ключевые факты (проверены замерами)

### 1. Bravo: четыре ценовые зоны, нет единого прайса

Bravo делится на четыре ценовые зоны, и они **НЕ совпадают с форматом магазина** (Superstore, Supermarket, Ekspress). Одна зона может содержать магазины разных форматов.

- Ценовая зона хранится в поле `stores.price_cluster` (измеренное значение, а не вывод из названия)
- **Показывать цену Bravo без выбора конкретного магазина нельзя** — у каждого филиала своя цена

### 2. Araz, SPAR, Neptun, Rahat: единая цена на всю сеть

Проверено на 8 филиалах Araz и 3 филиалах других сетей — цена одинакова независимо от филиала.

SPAR работает как премиальный формат Araz и держит тот же прайс.

### 3. Медианная выгода мала на базовых ценах, но велика на акциях

- У 62% товаров, присутствующих минимум в трёх сетях, **базовая цена одинакова**
- Медианная выгода от выбора сети на обычной цене: **2.9%**
- **ЦЕННОСТЬ ПРОДУКТА — В АКЦИЯХ**: медианная выгода там **26.7%**
  - У четверти товаров скидка больше 44%
  
**Интерфейс должен вести к акциям, а не к таблице базовых цен.**

### 4. Скидка считается от рынка, не от ценника сети

Настоящая скидка — это разница с **медианой обычных, неакционных цен** на тот же штрихкод в других сетях, а не от исторической цены конкретной сети.

⚠️ **4.6% акций имеют накрученную старую цену** — это накрутка, скрытая в формульчике «было 5 манатов, теперь 3 манатов».

### 5. Склейка товаров: EAN, отпечаток названия, триграммы

Товары объединяются по:
- EAN (если есть)
- Отпечатку названия (нормализованной версии)
- Похожести названий (символьные триграммы, порог 0.82, точность 96%)

**Карантин**: поле `products.quarantined = 1` означает, что склейка сомнительна. **Никогда не показывать карантинные товары пользователю.**

### 6. Весовые товары: килограммы, без штрихкода

`unit_type = 'kg_bulk'` — товары без штрихкода, цена указана за килограмм.

**Bazarstore особенность**: весовые товары продаются вариантами (1 kg, 250 gr, etc.) с пропорциональной ценой.
- **Сравнивать можно только килограмм с килограммом**

## Ловушки, на которых уже наступил

### Турецкая İ

В JavaScript и Dart: `'İ'.toLowerCase()` = `'i' + U+0307` (комбинирующий символ).

```javascript
'milka'.includes('MİLKA')  // ❌ false
```

**Решение**: нормализация текста должна:
1. Заменить турецкие символы: İ → I, Ə → A, Ö → O, Ü → U, Ç → C, Ş → S, Ğ → G
2. Опустить регистр
3. Сбросить комбинирующие знаки через NFD

### Региональные сокращения

- `qr` в азербайджанских названиях = **граммы** (qram), не что-то другое
- Голый хвост `kq` без числа = **весовой товар**
- `7 Lİ`, `10 LU` = **упаковка из N штук**

### Одинаковый штрихкод ≠ одинаковая фасовка

Если цены сходятся, а описания фасовки разные:
- ✅ Дефект описания, а не ошибка склейки
- Не переклеивать товары за это

### Слаг на Wolt может увести в другую страну

`grandmart` выглядит как бакинский магазин, отдаёт 596 товаров и грузится без ошибок.
Но это русскоязычная точка другой страны, медианная цена там **1014** против 1.4–4.4
в бакинских. Формально данные валидные, по сути мусор.

**Решение**: коннектор отклоняет магазин, у которого медиана цены вне диапазона
0.30–50 манатов, и пишет в лог почему. Проверка постоянная, а не разовая.

### Внутренний код нельзя выводить из названия

Сначала я брал хвостовые цифры названия как SKU. «Siyəzən Təzə Toyuq 1010» и
«Qələm Pensan 1010» получили один ключ — курица и ручка. История цен показала
47 фантомных изменений после первого же прогона.

**Решение**: только настоящий `id` товара из источника.

### NULL ≠ NULL в UNIQUE

`UNIQUE (chain_id, store_id, chain_sku)` не работает для сетей с единой ценой,
где `store_id` пустой: в SQLite и Postgres NULL не равен NULL, и появляются дубли.

**Решение**: отдельный уникальный индекс с `COALESCE(store_id, 0)`.

### Акции Bazarstore лежат в двух местах

В общем фиде `/products.json` поле `compare_at_price` заполнено только у 10.8%
вариантов. Остальные акции — в коллекции `endirimli-mehsullar`, оттуда же
дотягиваются штрихкоды, которых нет в основном фиде.

## Источник, которого нет у конкурентов

Все кассы в Азербайджане фискальные, на каждом чеке QR со ссылкой на портал
**e-kassa.gov.az** с составом чека и ценами.

- Данные из кассы точнее любой витрины: там цена, по которой реально пробили товар
- Покрывает магазины, куда скрейпером не залезть никогда
- Юридически чисто: это данные самого пользователя, нужно согласие и обезличивание

## Что уже проверено на конкурентах

`marketqiymeti.az` — единственный прямой конкурент, продуктовый, обновляется ежедневно.
Сети: Araz, Bazarstore, Birmarket, Oba. **Bravo у них нет.** Межсетевой матчинг
практически не работает: на карточке Coca-Cola 330 мл написано «1 marketdə mövcuddur».
Ни времени проверки цены, ни истории, ни филиалов.

## Стиль кода

- **Деньги**: `int` в гяпиках везде. Форматирование только на границе UI
- **История цен**: append-only таблица наблюдений, **никаких UPDATE по ценам**
- **Прозрачность**: каждое число, показанное пользователю, должно сопровождаться временем наблюдения

## Retail Price Intelligence Platform (`rpi/`, `warehouse/`)

Слоёная платформа данных поверх тех же правил (деньги в гяпиках, append-only история, зоны, карантин, акции против рынка). Работает только на синтетике (`rpi/synth`), реальных источников и скрейпинга в ней нет. Документация на английском: `README.md`, `docs/`.

- Слои: `bronze` (сырьё) → `silver` (Python/Polars) → `gold` (dbt, папка `warehouse/`); телеметрия в `ops`.
- Запуск: `make demo`, тесты `make test` (нужен Postgres 16), линт `make lint`.
- Старый пайплайн (`pipeline/`) не трогать: платформа берёт из него только `units.py` и `fingerprint.py` через `rpi/legacy.py`.
