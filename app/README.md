# app/ — клиент qiymət

Flutter 3.24+, Dart 3, Material 3, светлая и тёмная темы, локализации az / ru / en.

```bash
flutter pub get
dart run build_runner build --delete-conflicting-outputs
flutter gen-l10n
flutter test
flutter run --dart-define=QIYMET_API_URL=http://localhost:8000
```

> **Платформенные папки.** `android/` и `ios/` в репозитории нет — создайте их
> один раз: `flutter create --platforms=ios,android .` (в существующем проекте
> команда добавляет только недостающее). См. раздел «Что не проверено».

## Слои

```
data        api (dio + retrofit), dto, cache (drift), mappers, repositories
domain      модели freezed, без единой зависимости от Flutter и от сети
presentation экраны, провайдеры riverpod, go_router
design      токены и виджеты
core        normalizeAz и прочие утилиты без зависимостей
```

Правило одно: **виджет не вызывает dio**. Экран читает провайдер, провайдер
идёт в репозиторий, репозиторий знает про сеть и кеш. Между DTO и экраном стоит
слой мапперов, чтобы форма ответа сервера не протекала в разметку.

## normalizeAz

`lib/core/text.dart`. Порядок шагов важнее самих замен:

1. заменить заглавные `İ I Ə Ö Ü Ç Ş Ğ` на строчную латиницу;
2. **только теперь** `toLowerCase()`;
3. NFD и снятие диакритики U+0300–U+036F;
4. заменить оставшиеся строчные `ə ı` и прочие.

Если поставить `toLowerCase()` первым, поиск ломается на каждом слове с İ.
Проверено запуском:

```
'MİLKA'.toLowerCase()  ->  "mi̇lka"
                           U+006D U+0069 U+0307 U+006C U+006B U+0061
                                         ^^^^^^ комбинирующая точка
поиск «milka» в этой строке  ->  false
normalizeAz('MİLKA')         ->  "milka"   поиск находит  ->  true
```

Шаг 3 подчищает и уже разложенный ввод: если пришло `'I' + U+0307` вместо `İ`,
результат всё равно `i`.

NFD берётся из `unorm_dart`: в `dart:core` нормализации нет, а без неё `ğ` не
разложится в `g + U+0306`, и клиент разойдётся с серверной `qiymet_norm`.

## Дизайн-система

`lib/design/tokens/` — цвета, типографика, отступы. **Шкала отступов кратна
4**, магических чисел в виджетах нет: если нужного шага нет, он добавляется в
`Spacing`, а не мимо.

### PriceText

Единственное место в приложении, где деньги превращаются в текст.

```dart
PriceText(minor: 1399, oldMinor: 3469, emphasis: PriceEmphasis.cheapest)
// 13,99 ₼  3̶4̶,̶6̶9̶
```

Принимает `int` в гяпиках. Считает целочисленно — `1399 ~/ 100` и `1399 % 100`,
а не `1399 / 100`: деление дало бы `double`, то есть ровно тот float, которого в
деньгах быть не должно. Разделитель берётся из локали (`13,99` в az и ru,
`13.99` в en).

Старая цена показывается, только если она **строго больше** текущей: «старая
цена» ниже новой означала бы, что цена выросла, и зачёркивать там нечего.

### Дальтонизм

«Дешевле всех» и «дороже всех» различаются **не только цветом**. У каждого
состояния свой вес шрифта:

| состояние | вес | цвет |
|---|---|---|
| `cheapest` | w700 жирный | зелёный |
| `neutral` | w400 обычный | нейтральный |
| `priciest` | w500 средний | приглушённый терракотовый |

Разница в весе видна и на чёрно-белом экране, и человеку, который не различает
зелёный с красным. Цвет здесь третий канал, а не единственный. Проверяется
тестом `price_text_test.dart` — он сравнивает именно `fontWeight`, а не только
`color`.

### Шрифт

Inter (SIL OFL, файл лицензии рядом со шрифтами). Системный не годится: в
некоторых сборках Roboto нет `ə` (U+0259), и буква молча подменяется из
запасного шрифта — в азербайджанском тексте это видно сразу.

Покрытие **проверено разбором таблицы cmap** для всех четырёх начертаний:

```
Inter-Regular    глифов 2852   ВСЁ ЕСТЬ
Inter-Medium     глифов 2852   ВСЁ ЕСТЬ
Inter-SemiBold   глифов 2852   ВСЁ ЕСТЬ
Inter-Bold       глифов 2852   ВСЁ ЕСТЬ
```

Контрольная строка «Çuğundur, göbələk, şəkər tozu, ət və südlü məhsullar»
покрыта посимвольно, включая U+0259 `ə`, U+0131 `ı`, U+011F `ğ`, U+015F `ş`.
Кириллица для русской локали и знак маната U+20BC `₼` тоже на месте. Тот же
разбор повторяет тест `font_coverage_test.dart` — он читает ttf из ассетов и
падает, если шрифт подменят на неполный.

экономится 2.9%, а на акциях — 26.7%. Интерфейс должен вести к акциям.

## Онбординг: выбор магазина

Один экран, пропустить нельзя. `lib/presentation/screens/onboarding/store_picker_screen.dart`.

**Почему обязателен.** У сети с моделью цены `per_cluster` разброс между
собственными магазинами примерно такой же, как между разными сетями. На товаре
9150 из дампа: 447, 449, 449 и 475 гяпиков в четырёх магазинах Bravo — при том
что у Rahat 374, а у Araz 450. Показать «цену в Bravo» без магазина значит
взять одну из четырёх и выдать её за общую.

Сторожит `redirect` в роутере: пока `selectionCompleteProvider` даёт `false`,
любой путь уводит на `/onboarding`, а кнопка «Продолжить» неактивна.

**Слово «зона» на экранах не встречается ни разу** — проверено `grep` по всем
трём `.arb`. Пользователь выбирает свой магазин; группировка прайсов по
измеренным кластерам осталась во внутренних комментариях и в API.

### Несколько сетей, но один store_id

Выбор сетей множественный — человек ходит в две-три. А `store_id` в запрос
уходит один, и это не упрощение:

* у сетей с `price_model = 'single'` (Araz, SPAR, Neptun, Rahat, Bazarstore)
  прайс единый, и `/v1/stores` отдаёт для них **одну синтетическую запись** со
  `store_id: null` — выбирать филиал не из чего;
* цену меняет только выбор точки у `per_cluster`.

Поэтому набор сетей — фильтр показа, а `storeId` — то единственное, что реально
меняет цифры. Какие сети требуют выбора точки, берётся из ответа сервера, а не
из захардкоженного `'bravo'`: появится вторая такая сеть — код потребует выбор
сам, без правок.

### Геолокация и отказ

Разрешение спрашивается **только после** того, как пользователь нажал кнопку и
прочитал объяснение в диалоге. Системный диалог, выскочивший сам по себе на
первом экране, закрывают не читая — и отказывают навсегда, после чего вернуть
доступ можно лишь через настройки телефона.

Отказ — штатный исход, а не ошибка. `lib/core/geo.dart` различает пять случаев
(`LocationFound`, `LocationDenied`, `LocationDeniedForever`,
`LocationServiceOff`, `LocationFailed`), и у каждого есть продолжение: список
районов плюс полный список магазинов, а для «запрещено навсегда» — кнопка в
настройки.

Чипы районов показываются, **только если они реально что-то фильтруют**. Ряд
чипов, ни один из которых ничего не меняет, читается как поломка. Сейчас
`stores.address` в дампе пуст, поэтому чипы не появятся и экран покажет полный
список — см. «Известные ограничения дампа».

### Смена магазина выбрасывает кеш цен

`StoreSelectionController._apply` сравнивает новый `storeId` со старым и, если
он изменился, зовёт `CatalogCache.clearPrices()`. Без этого человек, переехавший
из одного магазина в другой, увидел бы цифры прошлой точки — и они выглядели бы
как обычные свежие цены, без единого признака подвоха.

Поменять выбор можно в «Настройки → Мои магазины»: тот же экран с
`isOnboarding: false`.

## Экран поиска

**Дебаунс 300 мс, поиск с третьего символа.** Три символа — не круглое число:
индекс на сервере триграммный, и на более коротком запросе он не применяется,
а запрос уходит в полный перебор каталога ради двадцати строк.

Дебаунс сделан через `autoDispose`, а не таймером. При смене запроса старый
провайдер уничтожается, взведённый в нём флаг `cancelled` становится `true`, и
ответ на устаревший текст не показывается. Это заодно снимает гонку «пришёл
ответ на предыдущий запрос и перекрыл новый» — таймер её не снимает.

Карточка результата: название, фасовка, минимальная цена, бейдж акции, число
сетей и **время наблюдения рядом с ценой**.

Пустое состояние — подсказки `süd`, `çörək`, `yumurta`, `şəkər`. Пустой экран с
одним полем не говорит человеку, что тут вообще можно искать.

### Оффлайн

Без сети отдаётся сохранённый ответ **на тот же самый запрос** с плашкой
«Нет интернета. Данные от 14:20».

Ключ кеша — нормализованный запрос плюс `store_id`. Это важнее, чем кажется:

* показать вместо ответа «последние виденные товары» было бы подменой — человек
  ищет молоко, а видит стиральный порошок под плашкой о времени;
* без `store_id` в ключе у сети с несколькими прайсами оффлайн подсунул бы цены
  чужой точки.

Отличаем «нет сети» от «сервер ответил ошибкой»: при ошибке сервера кеш не
показываем, потому что сервер жив и мог бы ответить иначе.

### Сканер

`mobile_scanner`, кнопка в поле поиска. Отсканированный EAN сразу ведёт на
карточку: промежуточный список из одной строки посреди магазина только отнимает
время. Форматы ограничены EAN/UPC — остальные добавляют ложных срабатываний на
ценниках и рекламе. Если штрихкода нет в базе, экран не закрывается: человек
пробует другую упаковку, не начиная сначала.

## Карточка товара

Название, бренд, фасовка, **штрихкод мелким шрифтом** — он нужен, чтобы сверить
с пачкой в руке, а не чтобы на него смотрели.

**Таблица цен**: у каждой строки цена, зачёркнутая старая и время последней
проверки. Строка «дешевле всех» выделена фоном, названием сети полужирным И
жирным начертанием цены — цвет здесь не единственный канал.

**Весовые товары.** При `unitType == 'kg_bulk'` карточка пишет словами «цена за
1 кг» и добавляет пояснение отдельной плашкой. Без этого человек сравнит цену
килограмма помидоров с ценой пачки печенья и сделает вывод наоборот.

**График за 30 дней** рисуется, только если данных хватает:
`points.length >= 3 && span >= 7 дней`. Иначе — строка «истории пока мало».
Линия из двух точек читается как утверждение «цена стабильна», хотя на самом
деле мы просто ещё не накопили наблюдений. График нарисован вручную через
`CustomPainter`: линия по точкам и две подписи — не та задача, ради которой
стоит тащить библиотеку со своим API и своим циклом обновлений.

**Следить за ценой** — целевая цена необязательна. Большинству нужно просто
«скажи, когда подешевеет», и требовать число значило бы отсечь их от механики,
ради которой приложение открывают второй раз. Ввод в манатах разбирается
целочисленно: `13,99` -> `1399`, без `double`.

**Добавить в список** — список живёт только на устройстве, в drift. На сервере
его нет и не нужно: это личное дело человека.

## Лента акций

`/deals` — главный экран. Базовые цены сетей почти одинаковы: у 62% товаров из
трёх и более сетей они совпадают, медианная выгода 2.9%. На акциях медиана
26.7%. Поэтому сортировка по настоящей скидке и есть единственный смысл экрана.

**Никакой персонализации и рекомендаций.** Подмешивать «интересное вам» в
честный порядок по выгоде значит терять то единственное, чем эта лента
отличается от витрины скидок.

### Главная строка

«Дешевле рынка на 60%», а не «−60%» с ценника: первое считается от медианы
обычных, неакционных цен на тот же штрихкод в ДРУГИХ сетях, второе сеть рисует
сама. По тапу открывается пояснение — на числах именно этой акции:

```
Сейчас          1.69 ₼
Сеть заявляет   6.80 ₼   −75%
Рынок           7.14 ₼   −76%
```

Абстрактное «мы считаем честно» никого не убеждает; три числа рядом убеждают.

Если настоящая скидка отрицательная, строка читается «дороже рынка на N%».
Молчать об этом нельзя: лента честная или никакая.

### Бейдж «старая цена накручена»

Позиции с `inflated` **не прячутся**. Спрятать значило бы стать ещё одной
витриной скидок; пометить — единственное, что отличает нас от остальных.
В пояснении к такой акции добавляется величина накрутки в пунктах.

### Фильтры

Категория, минимальная скидка, только мои сети. **Все три уходят на сервер.**
Клиентский фильтр при курсорной пагинации выбросил бы часть страницы, и человек
увидел бы три акции там, где их двадцать, а «загрузить ещё» подтягивало бы
такие же огрызки. Ради этого в API добавлены `?chains=` и `GET /v1/categories`.

Пороги скидки (10 / 25 / 40 / 50%) построены вокруг измеренных чисел: медиана
26.7%, у четверти товаров больше 44%.

Фильтр категорий показывается, **только если категории есть** — см.
«Известные ограничения дампа».

### Пагинация и обновление

Курсор, а не offset: витрина пересобирается после каждого прогона сбора, и
`OFFSET 40` показал бы товары, часть которых уже была выше. Догрузка начинается
за пол-экрана до конца, чтобы человек не упирался в спиннер.

**Ошибка догрузки не стирает список.** Человек прокрутил до конца — он не должен
потерять то, что уже прочитал: показывается строка с кнопкой «повторить», курсор
сохраняется. Pull-to-refresh начинает ленту заново; пустые состояния и экран
ошибки тоже прокручиваемые, иначе жест «потянуть вниз» до них не долетает.

### Шеринг картинкой

Находки пересылают в WhatsApp: там картинка разворачивается сразу, а ссылка
требует от получателя поставить приложение и найти тот же товар.

Карточка рисуется заново в offstage-слое, а не снимается со списка — так в
картинку не попадут соседние карточки и системная строка, а размер и тема будут
одинаковыми у всех отправителей. Снимок делается через `RepaintBoundary` из
самого Flutter, библиотека скриншотов не нужна.

## Список покупок

`/list` — список и ответ на вопрос «куда ехать».

Добавляется из поиска, из карточки, из ленты выгод и **текстом руками**.
У ручной позиции нет `productId`, а значит нет и не будет цены: человек написал
«хлеб», а какой именно — знает он один. Такая строка живёт как обычный пункт
списка, в сумму не входит и не портит её молча — рядом с итогом написано,
сколько строк исключено и почему.

### Итог: одна сеть впереди, разбиение — справкой

По замерам корзина из 30 товаров, разложенная на три сети вместо одной лучшей,
экономит медианно 4.2%. Поэтому блок итога устроен так:

```
Итог по 12 товарам
Bravo                              47.30 ₼
если разбить на 2 магазина         45.10 ₼
Bravo + Araz                     экономия 2.20 ₼

Обычно разбиение экономит немного. Стоит ли второй магазин
этих денег — решать вам.
```

Крупно и первой — одна лучшая сеть: обычный сценарий «съездил в один магазин и
всё купил». Разбиение идёт строкой ниже, **с абсолютной экономией в манатах**,
а не только процентом: два маната человек взвешивает сам, «−4.2%» звучит как
повод ехать. Ни кнопки «оптимизировать», ни выделения цветом у разбиения нет —
это справка, а не действие.

Варианты, которые не показываются вовсе:

* разбиение ровно за те же деньги — не выгода, а лишняя поездка;
* набор из трёх сетей, где третья не даёт ни одной лучшей цены — предложение
  лишнего магазина ради нуля;
* разбиение, которое не закрывает список целиком.

### Неполные сети не прячутся

Сеть, где нет трёх позиций из десяти, может оказаться самой дешёвой по остатку.
Показать её как «дешевле всех» было бы обманом, поэтому полные сети идут
впереди, а у неполных стоит число непокрытых позиций. Цены сети, требующей
выбора магазина, в сумму не идут вовсе: любая из нескольких зон, подставленная
в итог, сделала бы его выдумкой.

### Офлайн

Экран обязан открываться в магазине, где связь плохая. Поэтому источник
данных — **локальная база**, а не сеть: и позиции, и цены лежат в drift и
переживают перезапуск. Сеть нужна только чтобы освежить цифры; неудачное
обновление не ломает экран, а оставляет прежние цены и прежнее время проверки.

Цены тянутся **одним запросом на всю корзину** (`GET /v1/prices`), а не по
запросу на позицию: тридцать отдельных запросов в магазине со слабой связью не
доедут.

Синхронизируются именно цены. Сам список никуда не отправляется: он живёт на
устройстве, и на сервере его нет — это личное дело человека.

При смене магазина позиции остаются, а их цены обнуляются: они посчитаны для
прошлой точки, и показать их как свои было бы тем самым враньём, ради которого
инвалидация и затевалась.

### Свайпы

Влево — удалить, вправо — отметить купленным. Разные направления, потому что
«купил» и «передумал» — разное. Купленные уезжают вниз, а не исчезают: у кассы
человек может передумать.

## Чеки из фискальных касс

Отдельный источник, которого нет ни у кого. `/settings/receipts`.

Пользователь наводит камеру на QR с чека, приложение отправляет **ссылку как
есть** на бэкенд — не разбирает и не «улучшает» её. Разбор на сервере: там и
проверка домена (сервер ходит по присланному адресу, это SSRF), и обновление
парсера без выпуска новой версии приложения.

Подробности бэкенда, включая то, что **точный ответ портала подтвердить не
удалось** — в [api/RECEIPTS.md](../api/RECEIPTS.md).

### Согласие

Спрашивается **в момент первого сканирования**, а не на первом запуске: человек
уже держит чек в руках и понимает, о чём речь. Согласие, выданное «на всякий
случай» до того, как стало ясно зачем, — плохое согласие.

Текст приходит **с сервера** и показывается целиком, без «подробнее». Кнопка
согласия неактивна, пока текст не долистан до конца — галочка под нечитанным
текстом это ровно та практика, из-за которой согласия и оспаривают.

Отзыв и удаление живут на том же экране, а не спрятаны третьим уровнем в
настройках: право отозвать согласие бесполезно, если его надо искать. Отзыв
удаляет все чеки; обезличенные цены остаются, и текст согласия говорит об этом
прямо, до того как человек согласился.

Ссылка на закон Азербайджанской Республики «О персональных данных»
(№ 998-IIIQ) — в самом тексте согласия, на всех трёх языках.

## Известные ограничения дампа

Не дефекты приложения — дыры в данных, которые оно честно показывает.

* **Фотографий товаров нет нигде**: ни в `pipeline/schema.sql`, ни в API, ни в
  коннекторах — они их не собирают. Место под фото в карточке акции есть и
  переживёт появление картинок без переверстки: сейчас там иконка 56×56, а не
  серый прямоугольник в полкарточки. Чтобы фото появились, менять надо
  пайплайн, а не клиент.
* **`products.category` пуста на 100%** (0 из 36 214). Фильтр сделан
  end-to-end, включая `GET /v1/categories`, но список приходит пустым — и
  клиент прячет фильтр целиком.
* **`stores.lat/lon` пусты у всех 9 магазинов.** `distance_m` всегда `null`,
  сортировать по расстоянию нечем; в ответе `/v1/stores` есть
  `coordinates_known`, сейчас там ноль. Из-за этого же не появляются чипы
  районов в выборе магазина.
* **История в дампе — один прогон.** График цены не рисуется, экран пишет
  «истории пока мало»: это правильное поведение, а не ошибка.

## Время наблюдения

Правило, ради которого существует `ObservedAtText`: рядом с каждым числом,
которое видит пользователь, стоит время последней проверки. Сегодняшнее время
показывается как `14:20`, вчерашнее и старше — с датой. `14:20` без даты для
позавчерашней цены было бы враньём: человек прочитает это как «сегодня».

Время едет вместе с ценой и в кеш — иначе оффлайн цифры остались бы без него.

## Платформенные разрешения

`geolocator` не заработает без записей в манифестах. После
`flutter create --platforms=ios,android .` добавьте:

**`android/app/src/main/AndroidManifest.xml`**, внутрь `<manifest>`:

```xml
<uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
```

Точная геопозиция не нужна: мы ищем ближайший магазин, а не положение с
точностью до метра. `ACCESS_FINE_LOCATION` не запрашиваем сознательно — меньше
просим, охотнее дают.

**`ios/Runner/Info.plist`**:

```xml
<key>NSLocationWhenInUseUsageDescription</key>
<string>Yaxın mağazaları göstərmək üçün. Koordinatlar cihazdan kənara çıxmır.</string>
```

Текст на азербайджанском — основной язык аудитории; для локализованных вариантов
заведите `InfoPlist.strings` по языкам.

Для сканера штрихкода нужна камера.

**`AndroidManifest.xml`**:

```xml
<uses-permission android:name="android.permission.CAMERA" />
```

**`Info.plist`**:

```xml
<key>NSCameraUsageDescription</key>
<string>Barkodu skan edib qiyməti göstərmək üçün.</string>
```

`mobile_scanner` на Android требует `minSdkVersion 21`, на iOS — платформу 12.0
и более; проверьте `android/app/build.gradle` и `ios/Podfile` после
`flutter create`.

## Что перенесено из правил проекта

* **Деньги** — `int` в гяпиках во всех слоях, включая колонки drift
  (`IntColumn`, не `RealColumn`). Формат только в `PriceText`.
* **Время наблюдения** — рядом с каждой ценой, в том числе в кеше. Цена без
  времени наблюдения не показывается.
* **Карантин** — сервер отдаёт 404 на склейку с `quarantined = 1`, репозиторий
  превращает это в `null`, экран показывает «товар не найден». Для клиента
  карантинный товар неотличим от несуществующего, и так и задумано.
* **Bravo** — без выбранного магазина зоны показываются все, помечаются
  `requiresStoreSelection` и не участвуют в подсчёте лучшей цены.
* **Ключ кеша акций включает магазин** — лента для зоны C отличается от ленты
  для зоны B.

## Что проверено, а что нет

Проверено запуском:

* **алгоритм `normalizeAz`** — 23 случая, включая оба обязательных
  (`MİLKA -> milka`, `ÇUĞUNDUR -> cugundur`), контрольную строку целиком,
  идемпотентность и саму ловушку с `toLowerCase()`;
* **логика выбора магазина** — 19 проверок: «пропустить нельзя» во всех
  сочетаниях (пусто, сеть с единой ценой, сеть с привязкой к точке без
  магазина, магазин чужой сети), переходы отметить/снять/выбрать и сброс кеша
  ровно тогда, когда сменился `storeId`, и только тогда;
* **полнота переводов** — 135 ключей в каждом из трёх языков, все используемые
  в коде существуют, лишних нет, слова «зона» нет ни в одном;
* **разбор целевой цены** — 15 случаев плюс полный прогон 0.00…20.00: «0,5»
  даёт 50 гяпиков, а не 5, мусор отвергается, копейки не теряются;
* **арифметика графика** — проекция точек в холст, вырожденные случаи (плоская
  линия, совпадающее время) не делят на ноль, и правило «когда рисовать»;
* **машина состояний ленты** — 16 проверок: пагинация, защита от повторной
  догрузки, сохранение списка при ошибке догрузки, оффлайн без догрузки;
* **математика корзины** — 24 проверки, включая буквальное воспроизведение
  формулировки из задания (47.30 / 45.10 / экономия 2.20), отказ предлагать
  лишний магазин ради нуля, неполные сети и позиции, которые в сумму не идут;
* **чеки на сервере** — 65 тестов: разбор чека, деньги, время как бакинское,
  десять опасных ссылок отклонены (сервер ходит по присланному адресу — это
  SSRF), согласие, дедупликация, баллы, отзыв с удалением, обезличивание;
* **фильтры и пакетные цены на сервере** — 23 теста API против настоящего
  Postgres (всего в API 260 тестов): `chains` фильтрует и сохраняет порядок по настоящей
  скидке, работает с курсором, не путается в кеше, неизвестная сеть даёт пустой
  список, а не 500;
* **покрытие шрифта** — разбор cmap всех четырёх начертаний плюс отрисовка
  контрольной строки в растр;
* **синтаксис** — `dart format` разобрал все 83 файла без единой ошибки;
* **целостность связей** — ни одного битого относительного импорта.

**Не проверено сборкой.** В окружении, где писался этот код, у бинарника `dart`
нет доступа в сеть: соединение к любому внешнему хосту отваливается по
таймауту, хотя `curl` на тот же URL отвечает за полсекунды. Без сети не
отрабатывает `pub get`, а значит не запускались:

* `dart run build_runner build` — поэтому в репозитории **нет** сгенерированных
  файлов `*.freezed.dart`, `*.g.dart` и `lib/l10n/app_localizations.dart`.
  Без них проект не компилируется: это нормальное состояние Flutter-проекта
  до первой генерации, но пока она не выполнена, `flutter analyze` будет
  ругаться на отсутствующие `part`-файлы;
* `flutter analyze` и `flutter test` — написано 11 тестовых файлов
  (`text_test`, `price_text_test`, `font_coverage_test`, `packaging_text_test`,
  `store_selection_test`, `store_selection_controller_test`,
  `price_history_test`, `offline_search_test`, `deal_filters_test`,
  `deals_feed_test`, `basket_test`), но ни один не выполнялся;
* `flutter create` для `android/` и `ios/`.

Три команды приводят проект в рабочее состояние:

```bash
flutter create --platforms=ios,android .
flutter pub get && dart run build_runner build --delete-conflicting-outputs
flutter gen-l10n && flutter analyze && flutter test
```

Ожидаемо всплывут мелочи, которые ловит только компилятор: версия пакета в
`pubspec.yaml`, которой нет под текущий SDK, или расхождение имени
сгенерированного класса. Это правки на минуты, но честнее сказать заранее, что
они будут, чем утверждать, что всё соберётся с первого раза.
