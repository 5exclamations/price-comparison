# Платформенные сборки

Что настроено, что проверено и что осталось. Читать перед первой сборкой.

## Настроено

| | Android | iOS |
|---|---|---|
| идентификатор | `az.qiymet.app` | `az.qiymet.app` |
| минимальная версия | `minSdk = 21` | `IPHONEOS_DEPLOYMENT_TARGET = 15.0` |
| геолокация | `ACCESS_COARSE_LOCATION` | `NSLocationWhenInUseUsageDescription` |
| камера | `CAMERA`, `uses-feature required=false` | `NSCameraUsageDescription` |
| название | `res/values*/strings.xml` (az, ru, en) | `CFBundleDisplayName` + `*.lproj` |
| иконка | `mipmap-*/ic_launcher.png` | `AppIcon.appiconset`, 15 размеров |
| сплэш | `values-v31/styles.xml` + `launch_background.xml` | `LaunchImage.imageset` |

### Почему coarse, а не fine

Точное местоположение нужно навигатору. Нам — отсортировать список магазинов
по близости, и квартала для этого хватает. Просить точку с точностью до метра
ради сортировки списка значит брать больше, чем нужно для работы, и объяснить
это человеку нечем. Отказ от геолокации остаётся штатным исходом: район
выбирается руками.

`geolocator_android` своих разрешений в манифест не добавляет — проверено по
его `AndroidManifest.xml` в pub-cache, — так что в собранном приложении будет
ровно то, что перечислено выше.

### Почему minSdk 21, хотя Flutter ставит 24

В Азербайджане заметная доля рынка — телефоны на Android 5–6, а приложение
считает деньги в магазине, то есть нужно именно тем, кто их считает.

Планка проверена по каждому плагину, а не на глаз:

| плагин | требует |
|---|---|
| `mobile_scanner 5.2.3` | `minSdkVersion 21` |
| `sqlite3_flutter_libs 0.5.42` | `minSdk = 21` |
| `share_plus 10.1.4` | `minSdk 19` |
| `geolocator_android 4.6.2` | своего минимума не ставит |

21 — это потолок самого требовательного. Ниже не опустить: манифест не
соберётся.

### Тексты разрешений

Лежат в `ios/Runner/{az,ru,en}.lproj/InfoPlist.strings` и зарегистрированы
в `project.pbxproj` (`knownRegions`, `PBXVariantGroup`, фаза Resources) —
без этой регистрации Xcode не кладёт `.lproj` в бандл, и человек видит
английский текст вместо своего.

Правило для всех трёх языков: сказать **зачем** и **что будет при отказе**.
Системный диалог — единственное место, где человек решает, доверять ли
приложению, и «Приложению нужен доступ к камере» этому решению не помогает.

### Иконка

Рисуется самим приложением: `flutter test tool/make_icons_test.dart`.

Не `flutter_launcher_icons`: тот пакет делает ровно это же — раскладывает один
PNG по размерам, — но исходный PNG всё равно надо откуда-то взять. Здесь он
рождается из токенов дизайн-системы, поэтому цвет и шрифт совпадают
с приложением по определению, а не по внимательности. Заодно рендер знака `₼`
в иконке проверяет, что выбранный шрифт этот символ содержит.

## Не проверено сборкой

**Ни один из артефактов не собран.** Причины конкретные, и обе внешние.

### Android: нет SDK

```
flutter build appbundle --release
[!] No Android SDK found. Try setting the ANDROID_HOME environment variable.
```

Всё, что нужно, чтобы это заработало:

```bash
brew install --cask android-commandlinetools
export ANDROID_HOME=/opt/homebrew/share/android-commandlinetools
sdkmanager --install "platform-tools" "platforms;android-35" "build-tools;35.0.0"
yes | sdkmanager --licenses
flutter build appbundle --release
```

### iOS: упирается в сеть, а не в окружение

Xcode 26.5 на месте, симулятор iPhone 16 доступен. CocoaPods **не нужен**:
Flutter 3.47 подключает плагины через Swift Package Manager. Сборка дошла до
загрузки зависимостей и остановилась там:

```
Xcode is fetching Swift Package Manager dependencies. This may take several minutes...
  Fetching from https://github.com/simolus3/CSQLite.git...
xcodebuild: error: Could not resolve package dependencies
```

`CSQLite` — это нативная часть drift. Она тянется с GitHub при первой сборке
и кешируется в `~/Library/Caches/org.swift.swiftpm`. При живой сети команда
проходит без дополнительной настройки:

```bash
flutter build ios --debug --no-codesign
```

## Что осталось сделать руками

1. **Ключ подписи Android.** `android/app/build.gradle.kts` читает
   `android/key.properties`; пока файла нет, release подписывается отладочным
   ключом — `flutter run --release` работает, а Play такой артефакт не примет.
   Это сделано намеренно: случайно выложить нечем.

   ```properties
   storeFile=/абсолютный/путь/qiymet-upload.jks
   storePassword=...
   keyAlias=upload
   keyPassword=...
   ```

2. **Team ID для iOS.** Подпись не настроена: `--no-codesign` собирает, но на
   устройство не ставит. Нужен Apple Developer Program и `DEVELOPMENT_TEAM`
   в настройках цели Runner.

3. **Прогон на устройстве.** Ниже — то, что юнит-тестами не проверяется
   и остаётся на первый настоящий запуск.

## Что проверить на устройстве в первую очередь

Список не произвольный: это то, что на эмуляторе ведёт себя иначе, чем
в `flutter test`.

* **Шрифт.** Открыть поиск и ввести `şəkər`, `çörək`, `göbələk`. Буквы
  `ə ğ ş ç ö ü ı` должны рисоваться самим Inter, а не подменяться системным
  шрифтом. Подмена видна по чуть другой ширине и высоте букв.
  Контрольная строка: «Çuğundur, göbələk, şəkər tozu, ət və südlü məhsullar».

* **Тёмная тема.** Переключить систему в тёмную и посмотреть на список цен:
  «дешевле всех» обязано отличаться от остальных **и цветом, и весом шрифта**.
  Golden-тесты проверяют это на снимке, но контраст на настоящем OLED-экране
  на солнце — другой разговор.

* **Список покупок в авиарежиме.** Включить авиарежим и открыть вкладку
  «Список». Он обязан открыться с ценами из локальной базы и плашкой о времени
  последней проверки. Пустой экран или спиннер — поломка: список покупок нужен
  ровно там, где связи нет, — в магазине.

* **Разрешения.** При первом запуске сканера и при нажатии «использовать моё
  местоположение» прочитать текст системного диалога на всех трёх языках.
  Отказ обязан вести к работающему запасному пути, а не к тупику.

* **Сплэш.** На Android 12+ фон обязан быть фирменно-зелёным, а не белым:
  система рисует сплэш сама и `windowBackground` игнорирует, поэтому есть
  отдельный `values-v31/styles.xml`.
